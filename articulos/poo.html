Programación Orientada a Objetos (POO)

La Programación Orientada a Objetos organiza un programa partiendo de una idea sencilla: las cosas pueden representarse como objetosEntidades que reúnen estado, mediante propiedades, y comportamiento, mediante métodos. que contienen datos y acciones propios. En vez de dispersar variables y funciones, la POO las agrupa según la entidad que representan. Este enfoque ayuda a describir problemas reales, reutilizar soluciones y mantener el código cuando la aplicación crece.

Objetos y clases

Un objeto tiene propiedades, que describen sus características, y métodos, que representan lo que puede hacer. Una persona puede tener nombre, apellido y fecha de nacimiento; además puede comer, caminar o dormir. Al reunir esta información en una sola entidad, el programa expresa que los datos y las acciones pertenecen a la misma cosa, en lugar de tratarlos como piezas desconectadas.

Una claseMolde que describe el estado y el comportamiento disponibles para futuras instancias. es el molde común. Define qué propiedades y métodos existirán, pero no guarda datos particulares. Un objeto es una instancia: la realización concreta del molde con valores propios. Por eso Humano y Carro pueden compartir la idea de clase, aunque sus propiedades y sus acciones sean completamente diferentes.

Sintaxis tradicional: función constructora

Antes de la sintaxis class, JavaScript modelaba clases con funciones constructoras. Al usar newOperador que crea una instancia nueva y ejecuta la función constructora con ese objeto como contexto., se crea un objeto vacío; ese objeto pasa a ser thisReferencia al objeto que está siendo inicializado dentro del constructor. dentro de la función. Por eso, cada dato asignado a this termina formando parte de la instancia resultante, junto con los métodos que podrá invocar. 

function Vehiculo(modelo, placa, fabricante) {
  this.modelo = modelo;
  this.placa = placa;
  this.fabricante = fabricante;

  this.encender = function () {
    return this.modelo + " está encendido";
  };
}

const miVehiculo = new Vehiculo(
  "Nissan X-Trail", "AB123CD", "Nissan"
);

miVehiculo.modelo;     // "Nissan X-Trail"
miVehiculo.encender(); // "Nissan X-Trail está encendido"

Sintaxis ES6: class

ES6 incorporó una sintaxis más clara y cercana a la de otros lenguajes orientados a objetos. El método especial constructorMétodo que se ejecuta automáticamente al crear una instancia y prepara su estado inicial. recibe los datos iniciales, mientras que los demás métodos se declaran directamente en el cuerpo de la clase. Esta forma hace visible el molde completo de un vistazo y facilita separar la creación de objetos de las acciones que estos pueden realizar. 

class Vehiculo {
  constructor(modelo, placa, fabricante) {
    this.modelo = modelo;
    this.placa = placa;
    this.fabricante = fabricante;
  }

  encender() {
    return this.modelo + " está encendido";
  }
}

const miVehiculo = new Vehiculo(
  "Nissan X-Trail", "AB123CD", "Nissan"
);

Los cuatro fundamentos de la POO

Cada fundamento resuelve una necesidad distinta al diseñar programas más claros y fáciles de mantener. La encapsulación controla el acceso al estado; la abstracción reduce la complejidad visible; la herencia reutiliza una base común; y el polimorfismo permite usar una misma operación con resultados adecuados para cada objeto. Abre las cajas para relacionar la demostración visual con su implementación.

1. Encapsulación proteger el estado

Estado privadovelocidad: 020 km/h

La encapsulación agrupa el estado y el comportamiento en una misma unidad, y controla cómo se modifica la información interna. En este ejemplo nadie cambia la velocidad escribiendo sobre el valor privado directamente. El objeto ofrece acelerar() y verVelocidad() como una interfaz segura, de modo que la clase puede conservar reglas coherentes aunque cambie su implementación. 

class Carro {
  #velocidad = 0;

  acelerar() {
    this.#velocidad += 20;
  }

  verVelocidad() {
    return this.#velocidad;
  }
}

2. Abstracción mostrar lo esencial

Interfaz simpleMotor apagadoVehículo listoinyección → chispa → combustión

La abstracción expone una operación sencilla y oculta los pasos internos que el usuario no necesita conocer. Quien usa el vehículo solo pide encender(), sin aprender cómo funciona la inyección, la chispa o la combustión. Al separar el qué del cómo, el programa resulta más legible y los detalles internos pueden cambiar sin afectar a quienes consumen la clase. 

class Vehiculo {
  encender() {
    this.#inyectarCombustible();
    this.#generarChispa();
    return "Vehículo listo";
  }

  #inyectarCombustible() { /* detalle interno */ }
  #generarChispa() { /* detalle interno */ }
}

3. Herencia reutilizar y especializar

La herencia permite que una clase especializada reutilice capacidades de una clase base y agregue las suyas. Un avión sigue siendo un vehículo: puede encenderse y conservar datos generales como modelo o fabricante. A la vez, incorpora comportamientos propios, como despegar. Esta relación evita repetir el mismo código en cada tipo de vehículo y conserva una jerarquía fácil de entender. 

class Vehiculo {
  encender() { return "Encendido"; }
}

class Avion extends Vehiculo {
  despegar() { return "Despegando"; }
}

4. Polimorfismo una interfaz, varios resultados

mover()Rodando por la carreteraVolando por el cielo

El polimorfismo permite que objetos distintos respondan al mismo método de la manera apropiada para su propia clase. Tanto un carro como un avión entienden mover(), pero cada uno devuelve una acción diferente. El código que los usa no necesita conocer todos los detalles de cada tipo: invoca la misma interfaz y deja que cada objeto aplique su comportamiento particular. 

class Carro extends Vehiculo {
  mover() { return "Rodando por la carretera"; }
}

class Avion extends Vehiculo {
  mover() { return "Volando por el cielo"; }
}

[new Carro(), new Avion()]
  .map(vehiculo => vehiculo.mover());
